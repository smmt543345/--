# 05 · 批量导入与 AI 元数据补全

> 两项能力的共同目标是**录入提速**：批量导入解决「手里已有一份书单」的场景，
> AI 补全解决「只知道书名或 ISBN」的场景。都不联网也能用——没配 AI、请求失败时，
> 其余功能不受任何影响。

## 1. 设计原则

- **只建书目，不建副本**：批量导入与 AI 补全产出的是书目记录（Book）。副本是实物，
  有几本、什么品相只能由人确认——所以副本一律走详情页「＋ 添加副本」。
- **去重不合并**：批量导入只做「跳过重复」，不做字段合并。合并是备份导入的语义
  （03 §4），两者的规则不同，不混用。
- **失败不中断**：批量导入逐条创建，单条失败（如校验不过）记为跳过并报告原因，
  不因此中断整批；报告里逐条写明「第 N 行 · 原因」。
- **AI 是可插拔的能力**：应用核心（存储、搜索、借出）不依赖 AI；AI 只挂在录入表单
  上做补全建议，用户确认后数据才落库。

## 2. 批量导入

### 2.1 格式

**粘贴文本**（每行一本）：

```
书名
书名，作者
书名，作者，ISBN
9787108061690
```

行内用全角/半角逗号分隔（复用 `parseList` 的分隔符口径，`domain/text.ts`）。
一条行解析后至少要有「书名或 ISBN」之一才算有效行；其中书名必须含可读文字——
纯标点/符号的行（如分隔线、序号残留）按无效丢弃。
列数判定：末列是合法 ISBN 时按 ISBN 读、其余中列合并为作者（多作者用顿号）；
10/13 位但校验不过的 ISBN 形字符串按无效行丢弃。

**CSV 文件**（Excel 另存为 CSV 再导入）：

- 可选表头行：`title,author,isbn,publisher,publishDate,tags`（表头按内容识别，
  首行不是这些列名就当数据行）
- 无表头时按三列读：`书名,作者,ISBN`
- 解析自带 BOM 剥离；字段两侧空白一律 trim；引号包裹的最小支持（逗号在引号内
  不算分隔）

### 2.2 跳过规则（顺序判定）

| # | 判定 | 结果 |
|---|---|---|
| 1 | 解析不出书名与 ISBN | 跳过：无法识别 |
| 2 | 与**同批**前面某条书名规范化后相同（`normalizeTitle`，02 §7.3），或 ISBN 相同且非空 | 跳过：本批内重复 |
| 3 | ISBN 非空且库内已存在同 ISBN 书目 | 跳过：已有同样 ISBN |
| 4 | 书名非空且库内已存在同名（规范化后）书目 | **不跳过**：建新书目并返回「疑似重复」标记（与 02 §10.3 口径一致，只提示不阻断） |

### 2.3 报告

```
BulkImportReport {
  created: number;              // 成功新建
  skipped: { line: number; reason: string }[];   // 跳过明细（含粘贴/CSV 行号）
  suspected: { line: number; title: string }[];  // 疑似重复（已建，仅提示）
}
```

逐条通过 `createBook`（`db/books.ts`）创建；`createBook` 自带事务与写计数器，
批量层不再包事务（单条失败不影响其余）。

## 3. AI 元数据补全

### 3.1 协议与配置

- 协议：**OpenAI 兼容** `POST {baseUrl}/chat/completions`。凡兼容此协议的服务都能接：
  OpenAI、DeepSeek、通义、本地 Ollama 等——即「允许接入外部 AI」。
- 配置三项（settings 键）：`aiBaseUrl`（默认 `https://api.openai.com/v1`）、
  `aiApiKey`、`aiModel`（默认 `gpt-4o-mini`）。默认值只用于占位展示，用户可改。
- settings 表不进备份文件（03 §2），AI 密钥随设备、不随备份走。

### 3.2 隐私与安全

- 请求只发往用户自配的 `aiBaseUrl`，应用不经过任何第三方中转。
- 密钥输入框 `type="password"`；错误信息回显时不得包含密钥内容。
- 请求失败 / 超时（10s）→ 表单不变，显示人话错误（「连不上 AI 服务」「密钥可能无效」等）。

### 3.3 行为契约

- 入口：NewBookPage 表单上「AI 补全」按钮（未配置时按钮置灰并提示去设置页配置）。
- 输入：书名优先；书名为空则用 ISBN。
- 输出：AI 必须回复 JSON：`{ title, authors[], publisher, publishDate, tags[] }`。
  解析失败（模型不听话）→ 原样当错误提示，不入表单。
- **只填空字段**：表单里已有的值一概不覆盖（人填的优先于机器猜的）。
- 校验：回填的 publishDate 必须过 `isDateString`，否则丢弃该字段；其余字段 trim。

### 3.4 实现分层

- `features/books/ai.ts`：提示词拼装、回复解析与校验（纯逻辑，可 `node --test`）。
- `platform/ai.ts`：网络调用（`fetch`，10s 超时）。与 `files.ts` 同级——数据层与
  平台层的边界：features 层拿字符串进去、拿字符串/对象出来，不碰网络。

### 3.5 测试连接

设置页「AI 配置」区提供「测试连接」：发一次最小请求（`max_tokens` 极小），
成功显示「连接成功」，失败显示错误摘要。用于「外部 AI 接入」时让用户当场确认配置对。

## 4. 测试用例清单

- 粘贴解析：单字段/两字段/三字段、全角逗号、空行、只有空白、纯 ISBN、ISBN 校验失败的行
- CSV 解析：BOM、表头识别、引号内逗号、空列
- 跳过规则：批内书名重复、批内 ISBN 重复、库内 ISBN 重复、疑似同名不跳过
- 报告：created/skipped/suspected 计数与行号正确
- AI 回复解析：正常 JSON、带 ```json 围栏、模型胡话、缺字段、非法 publishDate 丢弃
- 只填空字段的合并逻辑

## 5. 不在本阶段

- AI 聊天式交互、智能标签建议、自然语言查书、书脊识别（都进 01 §10 后续项）
- 批量导入的「库内同名合并」语义（只提示，不合并）
