# 05 · 批量导入与 AI 元数据补全

> 两项能力的共同目标是**录入提速**：批量导入解决「手里已有一份书单」的场景，
> AI 补全解决「只知道书名或 ISBN」的场景。都不联网也能用——没配 AI、请求失败时，
> 其余功能不受任何影响。

## 1. 设计原则

- **批量导入可以建副本，但位置与数量必须来自人给的值，不猜**：书单行里的位置/副本数
  列、或导入框里选的默认值，决定建几本副本、放到哪、什么品相（默认「新」）。
  **AI 补全仍只产出书目**——AI 不知道你手里有几本、放哪，它只猜元数据。
  （P0-1 修订：原「只建书目，不建副本」原则被推翻，交互见 04 §11。）
- **去重不合并**：批量导入只做「跳过重复」，不做字段合并。合并是备份导入的语义
  （03 §4），两者的规则不同，不混用。
- **失败不中断**：批量导入逐条创建，单条失败（如校验不过）记为跳过并报告原因，
  不因此中断整批；报告里逐条写明「第 N 行 · 原因」。
- **AI 是可插拔的能力**：应用核心（存储、搜索、借出）不依赖 AI；AI 只挂在录入表单
  上做补全建议，用户确认后数据才落库。

## 2. 批量导入

### 2.1 格式

**粘贴文本**（每行一本）：

```
书名
书名，作者
书名，作者，ISBN
9787108061690
```

行内用全角/半角逗号分隔（复用 `parseList` 的分隔符口径，`domain/text.ts`）。
一条行解析后至少要有「书名或 ISBN」之一才算有效行；其中书名必须含可读文字——
纯标点/符号的行（如分隔线、序号残留）按无效丢弃。
列数判定：末列是合法 ISBN 时按 ISBN 读、其余中列合并为作者（多作者用顿号）；
末列是 10/13 位但校验不过的 ISBN 形字符串时，**只弃 ISBN 列、保留书名与作者**
（与 02 §7.3「无效 ISBN 不阻塞保存」精神一致）——只有既无书名又无合法 ISBN 的行才整体丢弃。

**CSV 文件**：

- 可选表头行（按内容识别，首行不是这些列名就当数据行）；无表头时按三列读：
  `书名,作者,ISBN`。
- 表头支持**别名自动识别**（大小写与空白不敏感），完整词典见 §2.2。
- 解析自带 BOM 剥离；字段两侧空白一律 trim；引号包裹的最小支持（逗号在引号内
  不算分隔）。
- **编码**：按 UTF-8（含 BOM）解析；不自动探测编码——Excel 的中文 CSV 常是 GBK，
  打开后发现乱码，提示「请另存为 UTF-8，或改用 xlsx 导入」。

**文本类文件**（B4 新增：`.txt` / `.md` / `.tsv` / `.json`）：

- `.txt` / `.md` / `.tsv`：按纯文本行读，**自动探测分隔符**（逗号、制表符、竖线 `|`、
  连续空格）——探测口径：取前 20 行的候选分隔符中每行均出现、且切分列数稳定（中位数≥2）
  的那一个；探测不出时按逗号口径处理（复用 `parseList`，全角/半角逗号都认）。
  注意「每行均出现」是**字面口径**：`.md` 的标题行/对齐行会让竖线候选失效而回退逗号——
  这个行为已被测试钉住，不要为个别格式加特例。解析后仍走 §2.2 的列映射与预览。
- `.json`：接受一个数组（或 `{ books: [...] }` 包装），每个元素一条书；
  字段名中英文都认（`title/书名`、`author/authors/作者`、`isbn/ISBN`、`publisher/出版社`、
  `publishDate/出版日期`、`tags/标签`、`location/位置`、`copies/副本数`）；
  不认识的字段忽略。数组为空或不是数组 → 报人话错误，不写库。

**Word 文件**（B4 新增：`.docx`）：

- 用 `fflate` 解压后读 `word/document.xml`，按顺序取**表格单元格与段落文本**：
  表格每行 = 一条书（单元格对应列）；文档末尾的散段也当行读（无分隔符时按文本行解析）。
- 解析结果与其他格式同构（进 §2.2 预览），表格列对不上时在预览里手动改列映射。
- `fflate` 仅用于解压，**动态 `import()`**，不把文档内容上传任何地方。
- `.doc`（97-2003 旧格式）不支持：提示另存为 `.docx`。

**xlsx / xls 文件**（P0-1 新增，不再要求「另存为 CSV」）：

- 用 SheetJS CE（`xlsx`）读取**第一个工作表**；`.xlsx` 与旧版 `.xls` 都支持。
- 解析结果与 CSV 完全同构：工作表首行是表头则走别名识别，否则按三列读。
- 实现分层：`src/features/books/xlsx.ts` 包住 SheetJS 的调用，只暴露
  `parseXlsx(bytes: Uint8Array) => ParsedBookRow[]`——页面与其余导入逻辑
  **不直接 import SheetJS**。依赖经 `import('xlsx')` **动态加载**，只在用户
  选择 xlsx 文件时才拉进内存（不进首屏包，01 §2）。
- 单元格只取值不取格式；空单元格同 CSV 空列处理。

### 2.2 列名映射、预览与批量默认值（P0-1）

用户的书单格式五花八门（Excel 导出的列名不统一），导入必须**先预览再写库**
（预览与默认值的交互形态见 04 §11.1，本节只定解析规则）：

1. **解析**：读取表头后按别名词典把每一列映射到字段；识别不出的列忽略。
2. **预览**：导入框里先展示前 5 行 + 每列的识别结果（「书名 ← 第 1 列『名称』」），
   识别错的可以手动改；改完确认才执行批量创建。
3. **批量默认值**：导入框提供三个默认选择——默认位置（默认「未分类」）、
   默认副本数（默认 1；填 0 = 只建书目不建副本）、默认品相（默认「新」）。
   **行值优先**：行里写了位置/副本数就按行的，没写才用默认值。
4. **位置不存在则自动新建**：行里写的位置名（或默认位置）库里没有 → 自动创建该
   位置（**新建为顶层位置**，parentId=null，按 02 §2 规则物化路径），不提示；
   创建失败（如空名）才记入报告。
5. **副本数校验**：副本数列不是合法非负整数 → 视为未填（用默认值，不跳过该行）；
   超过 99（`MAX_INITIAL_COUNT`）→ 按 99 截断并记入报告。

**别名词典**（独立文件 `features/books/import-mapping.ts` 的 `HEADER_ALIASES` 扩展，全部小写比较）：

| 字段 | 别名 |
|---|---|
| title | `title` `书名` `名称` `题名` `书` |
| author | `author` `作者` `著者` `编者` |
| isbn | `isbn` `ISBN` |
| publisher | `publisher` `出版社` `出版` |
| publishDate | `publishdate` `出版日期` `出版时间` `出版年` `年份` |
| tags | `tags` `标签` `分类` `类别` `tag` |
| location | `location` `位置` `存放地` `存放位置` `书架` `地点` |
| copies | `copies` `副本数` `册数` `数量` `本数` `count` |

新增字段进入 `ParsedBookRow`：`location: string`（位置名，空串=用默认）与
`copies: number | null`（`null`=用默认）。

### 2.3 跳过规则（顺序判定）

| # | 判定 | 结果 |
|---|---|---|
| 1 | 解析不出书名与 ISBN | 跳过：无法识别 |
| 2 | 与**同批**前面某条书名规范化后相同（`normalizeTitle`，02 §10.1），或 ISBN 相同且非空 | 跳过：本批内重复 |
| 3 | ISBN 非空且库内已存在同 ISBN 书目 | 跳过：已有同样 ISBN |
| 4 | 书名非空且库内已存在同名（规范化后）书目 | **不跳过**：建新书目并返回「疑似重复」标记（与 02 §10.1 口径一致，只提示不阻断） |

### 2.4 报告

```
BulkImportReport {
  created: number;              // 成功新建书目
  copiesCreated: number;        // 新建的副本总数（P0-1）
  skipped: { line: number; reason: string }[];   // 跳过明细（行号对应原始文件行）
  suspected: { line: number; title: string }[];  // 疑似重复（已建，仅提示）
  warnings: { line: number; reason: string }[];  // 已建成但有情况（副本数截断/位置建不出）；**不是跳过**，不能混进 skipped
}
```

逐条通过 `createBook`（`db/books.ts`）+ `createCopy`（`db/copies.ts`）创建；
两者各自自带事务与写计数器，批量层不再包事务（单条失败不影响其余）。
副本创建失败（如位置写入异常）不影响该书目已创建的事实——报告 `copiesCreated`
如实反映实际建成的副本数。

## 3. AI 元数据补全

### 3.1 协议与配置

- 协议：**OpenAI 兼容** `POST {baseUrl}/chat/completions`。凡兼容此协议的服务都能接：
  OpenAI、DeepSeek、通义、本地 Ollama 等——即「允许接入外部 AI」。
- 配置三项（settings 键）：`aiBaseUrl`（默认 `https://api.openai.com/v1`）、
  `aiApiKey`、`aiModel`（默认 `gpt-4o-mini`）。默认值只用于占位展示，用户可改。
- settings 表不进备份文件（03 §2），AI 密钥随设备、不随备份走。

### 3.2 隐私与安全

- 请求只发往用户自配的 `aiBaseUrl`，应用不经过任何第三方中转。
- 密钥输入框 `type="password"`；错误信息回显时不得包含密钥内容。
- 请求失败 / 超时（10s）→ 表单不变，显示人话错误（「连不上 AI 服务」「密钥可能无效」等）。

### 3.3 行为契约

- 入口两个：① NewBookPage 表单上「AI 补全」按钮（未配置时按钮置灰并提示去设置页配置）；
  ② **扫码命中后自动跑一次**（阶段 D，04 §11.12）——扫码本身不依赖网络，只有随后的元数据补全需要 AI；未配置时只填好 ISBN 并提示去配置。
- 输入：书名优先；书名为空则用 ISBN。
- 输出：AI 必须回复 JSON：`{ title, authors[], publisher, publishDate, tags[] }`。
  解析失败（模型不听话）→ 原样当错误提示，不入表单。
- **只填空字段**：表单里已有的值一概不覆盖（人填的优先于机器猜的）。
- 校验：回填的 publishDate 必须过 `isDateString`，否则丢弃该字段；其余字段 trim。

### 3.4 实现分层

- `features/books/ai.ts`：提示词拼装、回复解析与校验（纯逻辑，可 `node --test`）。
- `platform/ai.ts`：网络调用（`fetch`，10s 超时）。与 `files.ts` 同级——数据层与
  平台层的边界：features 层拿字符串进去、拿字符串/对象出来，不碰网络。

### 3.5 测试连接

设置页「AI 配置」区提供「测试连接」：发一次最小请求（`max_tokens` 极小），
成功显示「连接成功」，失败显示错误摘要。用于「外部 AI 接入」时让用户当场确认配置对。

## 4. 测试用例清单

- 粘贴解析：单字段/两字段/三字段、全角逗号、空行、只有空白、纯 ISBN、ISBN 校验失败的行（书名有效时保留行、ISBN 置空）
- CSV 解析：BOM、表头识别、引号内逗号、空列
- xlsx 解析：首工作表读取、无表头三列、表头别名、空单元格（P0-1）
- 列名映射：别名命中（含中文列名）、识别不出的列忽略、手动改映射（P0-1）
- 批量默认值：行值优先、无位置列落默认位置、副本数 0=只建书目、副本数非法回退默认、
  副本数超 99 截断（P0-1）
- 位置自动新建：行内新位置名 → 自动创建并落位（P0-1）
- 文本类格式（B4）：分隔符自动探测（逗号/制表符/竖线/多空格）、探测不出回退逗号、
  `.json` 数组与 `{books:[]}` 包装、中英文字段名、非数组报错不写库
- Word（B4）：表格每行一条书、段落文本也当行、列对不上时手动改映射、`.doc` 提示另存
- 跳过规则：批内书名重复、批内 ISBN 重复、库内 ISBN 重复、疑似同名不跳过
- 报告：created/copiesCreated/skipped/suspected 计数与行号正确
- AI 回复解析：正常 JSON、带 ```json 围栏、模型胡话、缺字段、非法 publishDate 丢弃
- 只填空字段的合并逻辑

## 5. 不在本阶段

- AI 聊天式交互、智能标签建议、自然语言查书、书脊识别（都进 01 §10 后续项）
- 批量导入的「库内同名合并」语义（只提示，不合并）
- 条形码扫码（阶段 D 的内容，规范见 04 §11.12）；免费 ISBN 元数据源（阶段 D **否决**，理由见 01 §7 决策 D11）
- **PDF 与图片 OCR 导入（B4 定案不做）**：PDF 表格识别经常串行错位、图片中文 OCR 准确率一般，且都要引入很大的依赖；实际用法直接复制粘贴更稳（05 §2.1）
